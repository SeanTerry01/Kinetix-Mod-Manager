# Kinetix Mod Manager: Future Development Roadmap

This document tracks potential improvements, architectural refinements, and new features to enhance the accessibility and power of the manager. (Now a multi-game suite covering Stardew Valley, Skyrim Special Edition, Fallout 4, and Moonlight Peaks.)

STATUS, 2026-08-02: everything proposed in sections 1-3 and section 6 has shipped, with five exceptions,
all of them listed under "What is actually left" at the end of section 6. Items below are struck through as
they ship, so anything NOT struck through is either genuinely outstanding or waiting on something external.

---

## 1. Codebase Health & Refinement
*   ~~**Refactor Form1.cs**: Move logic into dedicated service classes~~ — **Done.** `SoundEngine.cs`, `NexusService.cs`, and `ModFileSystem.cs` have been extracted. `Form1.cs` is now a UI orchestration layer only.
*   ~~**API Key Security**: Store the Nexus API key encrypted at rest~~ — **Done.** Windows DPAPI (`ProtectedData.Protect`) is used; the key is never written as plain text.
*   ~~**Enhanced Error Handling**: Replace silent catch blocks with spoken error messages that explain *why* an action failed~~ — **Done.** `FriendlyError` turns the common IO/network failures into a spoken sentence ("Disk Full", "Access Denied") rather than a silent no-op.
*   ~~**Unit Testing**: Implement basic tests for core logic like version comparison and manifest parsing~~ — **Done.** 220 tests as of 2026-08-02, covering manifest parsing, version handling, FOMOD conditions/installs, save parsing, INI editing, Bethesda layout, Steam library detection, BepInEx plugin identity, and keybind export parsing. The test project compiles the self-contained source files directly rather than referencing the WinForms app, so a new testable class needs a `<Compile Include>` line in `KinetixModManager.Tests.csproj`.

## 2. Immediate Fixes & UX Improvements
*   ~~**API Rate Limit Awareness**: Add a "Credits Remaining" display for non-premium Nexus users~~ — **Done.** The API-request counter shows remaining daily/hourly Nexus credits.
*   ~~**Visual Accessibility (Low Vision)**: "High Contrast" and "Large Text" modes~~ — **Done.** Both are in Settings -> Display and apply across the whole window, including the in-window views and prompts.
*   ~~**Dependency Tree View**: Show which mods depend on the selected mod before allowing a deletion~~ — **Done.** The dependency view plus a reverse-dependency warning on delete.

## 3. New Feature Ideas

### A. Dependency "One-Click" Resolver — Done
*   ~~Automatically find and queue all missing required mods for a newly installed mod.~~ — **Done.** The requirements check finds missing dependencies and installs them in one action.

### B. Mod Conflict Detection — Done
*   ~~Scan mod folders for overlapping file changes and warn about conflicts between active mods.~~ — **Done.** The file-conflict check reports every contested loose file, feeds the Setup Health Check, and "Choose File Conflict Winners" lets a specific file be awarded to a specific mod regardless of overall priority.

### C. Profile Sharing & Portability — Done
*   ~~Export/Import profiles as a single package (JSON + Mod List) so users can share setups.~~ — **Done** via profiles and Collections export/import. One refinement is still open — bundling a Collection as a zip with an embedded readme and pinned file IDs — see section 6.

### D. Integrated Mod Notes — Done (text notes); voice notes deferred indefinitely
*   ~~Allow users to attach personal text notes to specific mods, read out when the mod is selected.~~ — **Done** (`AppSettings.ModNotes`), also searchable from the Installed tab and filterable via the "Has a Note" status.
*   **Voice notes** — deferred indefinitely, not abandoned; may be picked up later. Worth knowing before starting: nothing in the manager records audio today, so this would be its first use of a microphone — device selection, permissions and storage of the recordings are all new ground rather than an addition to something existing. A typed note also keeps properties a recording doesn't (searchable, readable at any speed, survives being copied between machines), so any voice note is probably best stored *alongside* a text note rather than instead of one.

### E. "Broken Mod" Detection — Done
*   ~~Warn about mods known to be broken in the latest game version, even with no Nexus update.~~ — **Done** using the community compatibility data: SMAPI's mod-compatibility list for Stardew, LOOT's masterlist for Skyrim/Fallout 4.

### F. Multi-Game Support — Done
*   ~~Adapt the core engine beyond Stardew Valley~~ — **Done (v1.1.0–v1.2.0, extended 2026-07).** The manager fully supports Stardew Valley, Skyrim Special Edition, Fallout 4, and Moonlight Peaks, each with its own wiki, walkthroughs, accessibility-suite installer, and game-driven sound theme. Moonlight Peaks added a third mod layout (BepInEx plugins) alongside the Stardew manifest and Bethesda staged layouts. Per-game constants live in `GameProfiles.cs`, which is where a fifth game starts.

## 5. Recently Completed (through July 2026)

Many of the ideas in sections 1-3 above have since shipped. For the record, the manager now includes:
*   Enhanced spoken error handling (FriendlyError), unit tests, High Contrast / Large Text, API credits display, dependency tree view + reverse-dependency delete warning, one-click requirement resolver, broken-mod detection (SMAPI + LOOT), per-mod notes, and profile/Collections sharing.
*   Accessible FOMOD installer, controls/README viewer, mod changelog/description viewers, multi-provider AI assistant + log diagnosis, MO2 import, LOOT auto-sort, load-order export/import, and Wine/Linux support.
*   **July 2026 batch:** Fallout 4 archive-invalidation ("Load Loose Mod Files") toggle; deployment tools (Verify / Rebuild / **Purge**); **root-folder mod support** (ENB, ReShade, MO2-style Root\ folders); an **accessible INI editor** for game settings; the **Setup Health Dashboard** ("Check My Setup") aggregating the requirements, broken-mod, and file-conflict checks into one spoken summary; a **game-update / script-extender guardian** that warns once when a Steam/GOG update changes the game exe version so SKSE/F4SE and DLL plugins can be updated before launch; **plugin-limit awareness** (255 regular / 4096 light-ESL slot tracking with spoken usage and near-cap warnings); and an **accessible savegame manager** (list saves with character/level/location/playtime/date, warn when a save needs a plugin no longer active, back up / recycle saves) with a byte-level Skyrim/Fallout 4 save parser.

## 6. Proposed Features & Backlog (added 2026-07-06)

Ideas for things other managers (Vortex, MO2, the Nexus app) have that we don't, or accessibility-first
features nobody else does. Effort is a rough guess. Stars mark the recommended next picks.

### Tier 1 — real gaps, high value, strong fit

*   ~~**Game-update / script-extender guardian** [medium] ⭐~~ — **Done.** Every time a Skyrim/Fallout 4 session
    loads, the manager records the game exe's version; if it changed since last time, it warns once (spoken +
    dialog) that the game was updated from version X to Y and that SKSE/F4SE and DLL plugins likely need a matching
    update, offering to open the script-extender page. One-shot per update, not a persistent nag; no-ops for
    Stardew or an unreadable exe (Wine). Stored in AppSettings.LastSeenGameVersion.
*   ~~**Plugin-limit awareness** [low-medium] ⭐~~ — **Done.** "Plugin Slot Usage" (Mods menu / Ctrl+Shift+U)
    speaks "X of 255 regular plugins used, N remaining, M of 4096 light plugins used" and a warning when a pool is
    near/over its cap. Counts implicit base-game/DLC masters (present on disk) toward the regular cap and uses the
    TES4 light flag (via ReadPluginFlags) so ESL-flagged .esp files count as light. Warns automatically once per
    approach when the Plugin Order list is focused, and contributes a finding to the Setup Health Check.
*   ~~**Setup Health Dashboard** [low — mostly aggregation] ⭐~~ — **Done.** "Check My Setup" (Mods menu /
    Ctrl+Shift+K) runs the requirements check (missing masters, script extender, Nexus requirements), the
    known-broken/incompatible check, and the file-conflict check in one pass and gives a single spoken summary
    broken down by category ("Setup health check found 3 problems: 1 missing requirement, 2 broken or incompatible
    mods."). Each finding keeps its own Enter/Delete/AI actions. The game-update guardian and plugin-limit checks
    below will fold into the same command once they exist.
*   ~~**Savegame manager** [medium-high]~~ — **Done.** "Manage Save Games" (Mods menu / Ctrl+Shift+V) lists every
    Skyrim SE / Fallout 4 save with character, level, location, playtime and date, reads each save's embedded plugin
    list, and flags saves that need a plugin no longer active (mod removed/disabled). Enter speaks full details
    (incl. the missing plugins), B backs up the save + co-save, Delete sends them to the Recycle Bin. Byte-level
    parser in SaveGame.cs handles the uncompressed headers plus Skyrim's LZ4/zlib-compressed body (K4os.Compression.LZ4);
    covered by unit tests across all three compression modes + Fallout 4.

### Tier 2 — parity polish

*   ~~**Nexus "Tracked Mods" sync** [medium]~~ — **Done.** "Check Tracked Mods for Updates" (Mods menu /
    Ctrl+Shift+T) pulls the user's Nexus tracked list for the active game, intersects it with Nexus's
    recently-updated list (two bulk API calls), and shows the actionable mods: tracked-but-not-installed, and
    installed tracked mods with a newer version. Enter opens the mod's Nexus files page. Detail lookups run only for
    the small recently-updated-and-tracked subset, keeping it light on the API quota.
*   ~~**Downloads history / re-install tab** [low-medium]~~ — **Done** (as a dialog, not a tab, to avoid touching
    core tab/F6 navigation). "Reinstall a Downloaded Mod" (Mods menu / Ctrl+Shift+W) lists the per-game downloads
    folder newest-first with size + date; Enter reinstalls via the normal InstallFromZip path, Delete recycles the
    archive.
*   ~~**Persistent load-order rules** [medium-high]~~ — **Done.** MO2/LOOT-style "always load X after Y" rules,
    stored per game (AppSettings.LoadOrderRules) and folded into the plugin auto-sort (F8) alongside master
    dependencies and LOOT's own after-rules. "Add Load Order Rule for Selected Plugin" (Plugin Order tab selection
    = subject; Enter = load after target, B = load before) and "Manage Load Order Rules" (list + Delete) in the
    Mods menu.
*   ~~**Per-file conflict override** [medium]~~ — **Done.** "Choose File Conflict Winners" (Mods menu) lists every
    contested loose file; Enter cycles the winner through the mods that provide it, Delete reverts to priority order.
    Overrides persist per game (AppSettings.FileWinnerOverrides) and are applied by SyncDeployment after the priority
    walk (a stale override for a removed mod is ignored). Lets you keep mod A's textures but mod B's meshes even when
    A outranks B overall.

### Tier 3 — accessibility differentiators & nice-to-haves

*   ~~**First-run setup wizard** [medium]~~ — **Done.** A guided, spoken checklist (auto-shown on a fresh install
    in place of raw Settings, and re-openable from Help -> "Setup Wizard") shows the three setup steps — choose a
    game, set the Nexus API key, confirm the game folder — with live done / not-done status; Enter on a step
    launches its action (game chooser or Settings) and the checklist refreshes as steps complete.
*   ~~**Auto safety-backup before risky operations** [low]~~ — **Done.** A snapshot of the game INIs + plugins.txt
    + saved load order is taken automatically before purge, rebuild, and opening the INI editor (newest 8 kept per
    game). "Restore a Safety Backup" (Mods menu) lists them; Enter restores the files and load order and re-deploys,
    Delete removes one.
*   ~~**"Prepare for game update / restore after"** [low]~~ — **Done.** "Prepare for Game Update" (Mods menu) takes
    a safety snapshot and undeploys mods so a Steam/GOG update installs against a clean vanilla folder; "Restore Mods
    After Game Update" redeploys every enabled mod and runs the game-update guardian to flag any SKSE/F4SE mismatch.
    Pairs with the guardian.
*   ~~**Mod list filter/search** by category, note, or status [low-medium]~~ — **Done.** The Installed tab already
    had text (name/author) + category filters; the text search now also matches note text, and a new Status filter
    (All / Enabled Only / Disabled Only / Has a Note) sits beside the category filter. Filters compose.
*   ~~**Deeper Stardew support** [medium]~~ — **Done 2026-08-03.** Content Patcher config awareness shipped: a CP
    pack's `ConfigSchema` is read from its `content.json` and folded together with the generated `config.json`, so
    "Edit Mod Config" offers each setting as the list of values the author allows (Enter), with their description
    read out, and Delete reverts a setting by deleting it so Content Patcher regenerates it from the schema.
    Works before a pack has ever been run. Measured against a real 84-pack install: 39 packs declare settings,
    734 options in total, 647 of them with a fixed set of allowed values. Reader is `ContentPatcherConfig.cs`
    (lenient about the comments and trailing commas hand-written packs are full of), UI in
    `Form1.ContentPatcher.cs`, 13 unit tests. Original note follows. The **SMAPI
    install/update helper already exists** (the accessibility-suite installer installs SMAPI, and the update check
    detects + installs SMAPI updates), and any mod's `config.json` is already editable via "Edit Config" (Ctrl+E).
    The remaining piece — **Content Patcher token/config awareness** (surfacing a CP mod's config options/tokens) —
    is niche, needs real CP mods to validate, and is deferred rather than shipped half-baked.
*   ~~**Free space / cleanup tools** [low]~~ — **Done.** "Free Up Space (Clear Temporary Files)" (View menu) removes
    the app-update extraction folder and stale extractor/installer staging dirs the manager left in the system temp
    (matched by its own name prefixes, only ones older than an hour so a running install is safe) and reports how
    much was reclaimed. Downloaded archives are left for per-item removal in Reinstall a Downloaded Mod.

### Recommended order — nothing left to order
Tier 1, Tier 2 and Tier 3 are all done (2026-07-07), bar the one Tier 3 item marked deferred above
(Content Patcher token/config awareness). This heading previously still listed the whole of Tier 3 as
outstanding, which had been untrue since the day those features shipped.

### What is actually left

Four items, in two groups, plus voice notes (section 3D) deferred indefinitely and the two-copies-of-one-game
case parked below. Nothing else in this document is outstanding. (Content Patcher config awareness was the
fifth; it shipped 2026-08-03.)

**Buildable now:**
*   **FOMOD answer replay** in Collections — record the wizard choices made for a FOMOD mod so a Collection can
    reinstall it unattended instead of stopping to ask the same questions again.
*   **Zip-bundle Collections** — export a Collection as a single zip with an embedded readme, pinning exact file
    IDs rather than "latest main file", so a shared setup reinstalls as the same versions rather than whatever
    happens to be current.

**Parked by decision (2026-08-04), with the groundwork already understood:**
*   **Owning two copies of the same game (Steam and GOG at once)** — deliberately not built. A single-copy GOG
    user is correct as of 2026-08-04, when the GOG per-player data folder was fixed; only someone with BOTH
    copies installed is affected, and the Settings game-path field is a manual way through. Revisit if a real
    user hits it. The design was worked out before parking, so picking it up is not a fresh start:
    - The chooser itself is small: detect every copy, ask which when more than one is found and none chosen
      yet, remember it per game, and offer a Mods-menu item to switch later.
    - The substance is that three things kept per GAME are really per INSTALL, and sharing them fails
      SILENTLY, which is why a chooser alone would make matters worse rather than better:
      (1) `DeploymentManifest` (`deployment/<game>.json`) records what is deployed into the game folder — shared,
          it believes mods are deployed when they are in the other copy's Data folder, so mods read as enabled
          and simply are not there;
      (2) `AppSettings.LastSeenGameVersion` drives the game-update guardian — two copies are different builds,
          so every switch would announce a game update that never happened;
      (3) plugins.txt / INIs / saves — ALREADY per-install as of 2026-08-04, see `GameProfile.UserDataFolderFor`.
    - What should stay shared either way: the mod staging folder and the installed list, so a mod is installed
      once and deployed to whichever copy is active.
    - The alternative considered and not chosen: a separate game entry ("Skyrim Special Edition (GOG)"), which
      is what MO2 and Vortex both do. It gets the state separation free from the existing per-game machinery,
      at the cost of an extra entry in the games list and installing mods once per copy.

**Waiting on something outside the code:**
*   **Vortex import** — the implementation exists but has never been validated; it needs someone with a real
    Vortex setup. Same shape as the MO2 import, which was validated the same way.
*   **Downloadable language packs** — needs non-English translations to exist first. The `lang/` machinery and
    ~577 English keys shipped in 1.3.0; see docs on what is intentionally left in English.
*   ~~**Content Patcher config awareness** (Stardew)~~ — **Done 2026-08-03**, see Tier 3 above. It was shelved as
    "niche, needs real CP mods to validate against"; measuring an actual install settled that — 39 of 84 packs
    turned out to declare settings. The *token* half of the original idea (surfacing a pack's dynamic tokens,
    e.g. `{{Season}}`) was not built and is not proposed: tokens are how an author writes conditions, not
    something a player sets.
